# Arch Harness 演示脚本（V1.0 / D7 收官版）

> 面向面试与客户演示。按顺序走完约 12~15 分钟；每一步给出**操作 → 预期画面（截什么） → 讲解话术**。
> 所有步骤都在真实后端 + 真实 PDF 上跑通，不使用 mock 数据演示。

## 0. 演示前 5 分钟检查

| 项 | 命令 / 动作 | 通过标准 |
| :--- | :--- | :--- |
| 后端 | `cd mybackend && .venv/Scripts/python -m uvicorn app.main:app --port 8000` | `GET /health` 返回 `{"status":"ok"}` |
| 前端 | `cd mydemo && npm start` | `http://localhost:3000` 可打开 |

## 1. 登录（30 秒）

**操作**：打开 `http://localhost:3000/login`，输入 `admin@arch.com / Passw0rd123`，点「登录」。

**预期画面（截图 1）**：左侧深色品牌区（「把每一次审图，做成可追溯的对话」+ 三条能力说明），右侧极简登录表单；登录后跳到工作台。

**讲解话术**：

> 「登录走的是 JWT + refresh 双令牌：access 2 小时、refresh 7 天，刷新时静默续期，用户不会在填表单时被踢出去。这里的登录失败限流、账号禁用（`ACCOUNT_DISABLED`）都是后端判的，前端只负责呈现错误。」

---

## 2. 工作台（1 分钟）

**操作**：停在 `/dashboard`，先别点。鼠标依次划过三张统计卡。

**预期画面（截图 2）**：

- 顶部问候 + 今天日期；
- 三张统计卡：待审图纸 / 待处理批注 / 本周确认问题，带「其中 N 张预审中」「+0%」等副指标，整卡可点下钻；
- 待办中心：**指派给我的未关闭批注**，按严重度排序，每行「严重度圆点 + 标题 + 项目·图纸·页码 + 状态 chip + 相对时间」；
- 右侧最近项目（图纸数 / 未关闭批注数 / 更新时间）。

**讲解话术**：

> 「工作台不是装饰页：三张卡分别对应『图纸卡在哪一步』『批注压在谁手上』『AI 拦下的问题这周确认了多少』，每张卡都能点进对应筛选。待办中心是按『指派给我且未关闭』实时查的，点任意一条会直接跳到图纸上并高亮那条批注——从『知道有事』到『看到问题在哪』只有一次点击。」

---

## 3. 新建项目（45 秒）

**操作**：点右上「新建项目」→ 填「演示 · 研发中心」→ 业态选「办公」→ 阶段选「方案设计」→「创建项目」。

**预期画面（截图 3）**：极简弹窗（名称 / 业态 / 设计阶段），提交后 Toast「项目「演示 · 研发中心」已创建」，列表按最近更新排到最前。

**讲解话术**：

> 「项目是图纸、批注、预审任务的容器。创建项目的人自动成为项目负责人，这一步同时写 `project_members`——因为后面所有数据权限都挂在『你是不是这个项目的成员』上，功能权限管『能不能做这类操作』，数据权限管『能不能动这一条』，两层是分开的。」

---

## 4. 上传 PDF 图纸（1 分钟）

**操作**：进入刚建的项目 → 点「上传图纸」→ 拖入一个 PDF 图纸 → 等进度到 100% → 关闭弹窗。

**预期画面（截图 4）**：上传弹窗里的文件卡片（文件名、大小、类型徽标）、分片进度条；完成后图纸出现在列表首行，状态先「已上传 / 解析中」，随后变「解析完成」，并显示页数与大小。

**讲解话术**：

> 「上传是分片 + 合并：前端按固定大小切片并发上传，最后合并校验 sha256，断网重试不会产生半张图纸。文件名里的非法字符会在前端先被清洗并提示，避免后端 500。图纸版本用 `version + is_current` 表达，后续换版不会覆盖旧批注的坐标基准。」

---

## 5. 实时看 AI 预审（2 分钟，演示核心）

**操作**：图纸行内点「预审」（或详情页「发起预审」）→ 进入预审中心页 → 什么都不点，让过程自己跑。

**预期画面（截图 5，建议录屏 15 秒）**：

- 顶部任务头：图纸名 + 运行状态 chip（运行时有一个脉冲小圆点）+ 阶段文案（正在解析图纸 → 正在核对规范 → 正在归纳问题…）+ 百分比；
- 进度条**只增不减**；进入「等待设计师确认风险」时转琥珀色并暂停；
- 左侧思考链路：`agent_thought` / `tool_call` / `tool_result` / `issue_found` 按时间顺序流式追加，问题卡片带严重度、规范条文号、置信度；
- 断线时顶部出现「实时连接已断开 · 重新连接」，点一下从 `last_seq` 续传，不重复不丢事件。

**讲解话术**：

> 「预审不是一次 HTTP 等 30 秒，而是一条 SSE 事件流：`node_started / tool_call / issue_found / risk_interrupt` 这些事件按 `seq` 递增，前端记 `last_seq`，断线重连就从断点续传。进度条只增不减，因为用户最怕『明明走到 80% 又退回 40%』。这一步是整个产品最值钱的画面——AI 的每一步推理都能被审图人看懂、质疑、叫停。」

---

## 6. 风险确认弹窗（1 分钟，卡点一）

**操作**：等流程停在「等待设计师确认风险」→ 预审中心会自动弹出风险确认弹窗（或点顶部「去处理」）。

**预期画面（截图 6）**：深色遮罩上的弹窗，标题是风险中断标题，副标题「流程已暂停，请逐项判断这是「图纸问题」还是「已获豁免」」；右上角倒计时；每条风险卡片有等级圆点、检测值 vs 阈值、条文号，底部两个动作按钮。

**讲解话术**：

> 「这是 HITL（human-in-the-loop）的第一个卡点：模型发现了『可能违规但需要人判断』的风险，流程就**真的挂起**，不是弹个提示继续跑。用户逐条选『确认是图纸问题』或『标记为特殊豁免』，提交后流程从断点继续。倒计时是后端算的，超时会返回 422，前端提示『该确认已超时，请重新发起预审』——所有这些状态都落库，事后能查是谁在什么时候放行的。」

---

## 7. 报告确认（1 分钟，卡点二）

**操作**：流程跑完后点「查看报告初稿」→ 整页报告（摘要 / 问题清单 / 风险处置）→ 点「确认生成」。

**预期画面（截图 7）**：报告页顶部标题 + 版本号 + 「待确认」状态 chip，右上「退回修改 / 确认生成」；确认后 chip 变「已确认」，出现「下载正式文档」按钮，Toast「已确认，正式文档已生成」。

**讲解话术**：

> 「第二个卡点是报告：AI 只能给初稿，必须人确认才生成正式文档。这里特意做成整页而不是弹窗——报告要读完才能点确认。『退回修改』强制填不少于 10 个字的原因，退回后流程会带着这条意见重新分析，等于把人的判断写回了上下文。」

---

## 8. 批注下发（1.5 分钟）

**操作**：回到预审中心 → 问题清单勾选 2~3 条 → 点「采纳为批注草稿」→ 进入图纸画布 → 在右侧批注面板点「下发」→ 选责任人（张工 / 演示设计师）→ 确认。

**预期画面（截图 8）**：

- 问题清单多选后出现「已选 N 条 · 采纳为批注」操作条；
- 画布上出现红/橙/灰三色批注框，带序号气泡，右侧面板显示批注详情与时间线；
- 下发后状态 chip 从「待确认」变「已下发」，Toast「已下发」，责任人收到站内信。

**讲解话术**：

> 「AI 的问题不会直接变成任务，中间隔一步『采纳』：审图人可以把误报驳掉，只把真问题转成批注。批注锚定的是 PDF 坐标（`bbox + page_size + origin`），不是屏幕像素，所以换缩放、换设备、换图纸版本，框都还在原地。下发之后状态机是 `待确认 → 已下发 → 已修改待复核 → 已关闭`，每次流转都带 `row_version` 做乐观锁，别人刚改过会提示『已被他人修改，已为你刷新』。」

---

## 9. 消息通知（45 秒）

**操作**：点右上角铃铛 → 展开最近消息 → 点「查看全部」进消息中心。如果有未读，先指一下铃铛上的角标。

**预期画面（截图 9）**：铃铛下拉（未读高亮 + 相对时间）；消息中心列表：类型图标、标题、摘要、分类、时间、未读蓝条；顶部「全部已读」，Tab「全部 / 未读 / 系统」。

**讲解话术**：

> 「站内信是 outbox 模式：业务写库和事件入表在同一个事务里，消费者异步投递，失败重试带租约回收——所以不会出现『批注下发了但消息丢了』。点消息会按 `deeplink` 跳转，跳转地址只放行站内绝对路径，防开放重定向。未读角标轮询失败会降级提示，不会把整个页面拖垮。」

---

## 10. 切设计师身份看批注（1.5 分钟，权限对比）

**操作**：右上角头像 → 退出登录 → 用 `designer@arch.com / Passw0rd123` 登录 → 看工作台待办中心 → 进「批注协同」→ 点「指派给我」Tab → 点某条批注的「定位」。

**预期画面（截图 10）**：

- 侧边栏只剩 4 项（项目管理 / 预审中心 / 批注协同 / 消息中心），**没有系统管理**；
- 工作台待办中心列出指派给「演示设计师」的批注；
- 批注协同页「指派给我」Tab 高亮，表格列：严重度 / 批注（项目 · 图纸 · 页码）/ 状态 / 责任人 / 截止 / 更新 / 定位；
- 点「定位」跳到画布，目标批注**自动选中 + 高亮 3 秒**，右侧时间线自动加载。

**讲解话术**：

> 「同一条数据，换个角色看到的是另一个界面。菜单是后端按权限码算好下发的，前端不硬编码；按钮级也一样——设计师没有 `project:write`，所以项目列表里连『新建项目』和行操作都不渲染，而不是点了之后弹 403。刚才那条『定位』走的是深链 `?annotation=<id>`，画布页会翻到批注所在页、选中并高亮——这就是批注协同里『从列表到图面』的最短路径。」

**可选加演（30 秒，很有说服力）**：设计师状态下直接在地址栏输入 `/admin/users` → 落到 403 页（不是跳首页），说明路由守卫与页面级权限。

---

## 11. 系统管理（2 分钟，收口）

**操作**：退出，用管理员登录 → 侧边栏「系统管理」。

**11.1 用户管理**（截图 11）

- 表格 7 列：用户（首字母头像 + 创建时间）、邮箱、角色标签、项目数、状态（绿点 / 灰点）、最后登录、操作；
- 指一下自己那行的「禁用」——**置灰 + hover 提示「不能禁用当前登录账号」**；
- 点「新建用户」：用户名 / 邮箱 / 初始密码（可留空由后端生成，或点「生成」）/ 多选角色 / 状态 → 创建 → 弹出**一次性密码弹窗**，点「复制」变「已复制」；
- 对刚建的用户点「重置密码」→ 二次确认（提示对方登录态会失效）→ 新密码弹窗；
- 对某个用户点「禁用」→ 状态变灰、按钮翻成「启用」、Toast 确认。

**讲解话术**：

> 「用户管理有三条硬红线，全在后端判：不能禁用自己、不能移除自己的管理员角色、系统至少保留一名启用的管理员。前端只是把按钮置灰并给 tooltip，绕过前端直接调接口一样是 422。密码只在创建或重置的响应里出现一次，库里只有 bcrypt 哈希，审计日志里也会把 password 这类字段直接丢掉。」

**11.2 角色权限**（截图 12）

- 左列四个角色（管理员 / 审图专员 / 设计师 / 只读访客）+ 人数 + 权限数；
- 右侧只读矩阵：行是权限码（按 项目 / 图纸 / 预审 / 批注 / 通知 / 系统 分组，可折叠），列是角色，单元格 ✓ / —；
- 顶部黄色提示条「V1.0 仅支持查看，角色权限编辑将在 V2.0 开放」。

**讲解话术**：

> 「这张矩阵是真实渲染出来的：ADMIN 在库里也是显式绑定 16 个权限码，不靠 `*` 通配，所以矩阵不会出现『管理员那列全是空的』。V1.0 只读是产品决策——权限变更要走代码评审和数据迁移，不在界面上直接放开，所以单元格干脆不可点，而不是点了报错。」

**11.3 审计日志**（截图 13）

- 表格：时间 / 操作人 / 动作（彩色 chip）/ 对象 / IP / 详情摘要；
- 顶部筛选：动作下拉（新建用户、重置密码、禁用用户…）+ 起止日期 → 列表实时收敛；
- 刚才的新建、重置、禁用各有一条记录，IP 是真实客户端地址。

**讲解话术**：

> 「审计是只追加表：写操作和审计在同一个事务里提交，业务成功但没留痕是比业务失败更严重的事故。详情里只放脱敏摘要（角色、状态、邮箱），密码、token 这类键名在入口就被过滤掉。筛选用的动作枚举也是后端下发的，前端不维护第二套文案。」

---

## 12. 收尾（30 秒）

**操作**：回到「批注协同」全部批注页，指一下右上「共 N 条批注 · 点击定位回到图纸，自动选中并高亮」。

**讲解话术**：

> 「整个闭环到这一步就闭合了：AI 发现问题 → 人确认 → 批注锚定图面 → 指派到人 → 对方修改 → 复核关闭 → 全过程有审计和消息。V1.0 的目标不是『AI 替人审图』，而是把每一次判断都变得可追溯、可反驳、可复用。」

## 附：常见提问与回答

| 提问 | 回答要点 |
| :--- | :--- |
| 为什么不用 WebSocket？ | 预审过程是服务端单向推送 + 断点续传，SSE 更简单：HTTP/1.1 可用、天然支持 `Last-Event-ID`、过 Nginx 只需关缓冲。双向交互（评论）走普通 REST。 |
| 批注坐标为什么存 PDF 坐标？ | 存屏幕像素的话，换缩放/换设备/换图纸版本全部错位。落库时用 `toLocation()` 把屏幕框反算成 PDF 用户空间，渲染时再 `toScreen()` 正算回来。 |
| 权限前端做还是后端做？ | 后端是唯一防线（`require(perm)` + Service 层数据权限），前端只做两件事：菜单/按钮显隐（体验）、路由守卫跳 403（避免进空白页）。 |
| 首屏为什么这么快？ | 所有页面按路由懒加载，初始包 gzip 93 kB；PDF.js 只在画布页的 chunk 里，不拖累首屏。 |
| 有哪些没做完？ | DXF 在线渲染（目前只给下载）、批注框拖动与 8 控制点、缩略图条、项目成员管理界面（接口已就绪）。都在复盘文档里有明确边界。 |
